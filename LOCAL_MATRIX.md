# Free local Matrix development

This runs Synapse and PostgreSQL on your own computer. No VPS, domain, SMS provider or cloud account is needed. It does not make that computer reachable by distant phones. Both phones must be on the same trusted Wi-Fi, and the computer and Docker must stay running. Power, disk space and internet used to download images remain your responsibility.

Use disposable accounts: local HTTP exposes passwords, access tokens and metadata to network interception. Message bodies still use Matrix encryption, but HTTP cannot authenticate the server or protect sign-in. Use HTTPS for real accounts and public deployments. Do not forward port 8008 through your router or expose this setup through a public tunnel.

## 1. Install prerequisites

- Windows: Docker Desktop with its Linux/WSL2 engine, Python 3, Git, JDK 21 and Android SDK 36 if building the app. Use PowerShell. Substitute `py -3` for `python3` below when necessary.
- Linux: Docker Engine with Compose v2 and Python 3. Use the official Docker installation instructions for your distribution. Start Docker before proceeding.
- macOS: Docker Desktop and Python 3. The same Compose/Python commands work in Terminal.

Clone the repository, then open a terminal in `deploy/matrix`. On Windows use `cd deploy\matrix`. Files generated by the scripts are private and ignored by Git. Never add `.env.local`, `data-local`, account fixtures or database volumes to a public repository.

## 2. Find the computer's Wi-Fi IPv4 address

- Windows: run `ipconfig` and look for IPv4 Address under the connected Wi-Fi adapter.
- Linux: run `ip -4 address` and use the address of the connected Wi-Fi interface, not `127.0.0.1` or a Docker/VPN interface.
- macOS: System Settings → Wi-Fi → Details → TCP/IP shows the IP address. `ipconfig getifaddr en0` also works when Wi-Fi is `en0`.

An address such as `192.168.1.10` is an example. Use your actual private address in every command and phone field. Guest Wi-Fi/client isolation may prevent phones from reaching the computer. If a firewall prompt appears, allow the test port only on the private/local network, not public networks.

## 3. Prepare and start the server

From `deploy/matrix`, replace the example address:

```sh
python3 prepare-local.py --ip 192.168.1.10
docker compose --project-name rosevault-local --env-file .env.local -f compose.yaml -f compose.local.yaml up -d
docker compose --project-name rosevault-local --env-file .env.local -f compose.yaml -f compose.local.yaml ps
```

The helper generates a unique database password and registration secrets without printing them. On POSIX hosts it sets Synapse's numeric UID/GID to the creating user so private files can be read without world-writable permissions. It creates `data-local/homeserver.yaml` and `.env.local`; production `data`, `.env` and signing keys are separate. Public registration stays disabled. The local overlay skips Caddy and publishes Synapse only on the selected private IP at port 8008. PostgreSQL has no published port.

Open `http://YOUR_WIFI_IP:8008/_matrix/client/versions` in the computer browser, then in a phone browser on that Wi-Fi. Both should show JSON containing `versions`. If the phone cannot reach this page, fix Wi-Fi/firewall/Docker connectivity before diagnosing the APK. Do not enter personal credentials in that browser check.

## 4. Create two non-admin test users

```sh
python3 create-local-users.py
```

This creates `@demo-alice:rosevault.test` and `@demo-bob:rosevault.test`, with different random passwords. Open `data-local/test-accounts.json` privately on your computer to see the passwords and server address. The script registers inside the container; registration secrets are not sent across Wi-Fi. It refuses to overwrite an existing credential file or reset existing users. A partial failure preserves credentials; retry with a fresh `--prefix` and `--output` instead of deleting a real user's account.

The reserved `rosevault.test` identity is stable for this disposable server and does not need DNS. The app connects using the explicit private IP address. This is not phone-number authentication. Do not reuse these identities or the test database as a public production server.

## 5. Install the separate local app

From the repository root:

```sh
./gradlew -PtargetAbi=arm64-v8a :app:assembleLocal
```

On Windows use `gradlew.bat -PtargetAbi=arm64-v8a :app:assembleLocal`. The output is `app/build/outputs/apk/local/app-local.apk`. Omit `targetAbi` for a universal build or use `x86_64` for the test emulator.

Its launcher name is **RoseVault Local** and its package ends in `.local`. It installs beside the published RoseVault and owns separate vault/Keystore data. It never silently imports the main app's sessions or chats. The local manifest opts into Android cleartext only for this explicit development build type. The Matrix URL validator additionally permits HTTP only to literal RFC1918/loopback IPv4 addresses: public addresses, domain names, embedded credentials, queries and paths are rejected. Native networking does not necessarily honor Android manifest policy, so the client URL check is required too. Ordinary debug/release builds continue to require HTTPS.

On phone A, unlock RoseVault Local → Matrix. Enter `http://YOUR_WIFI_IP:8008`, Alice's full Matrix ID, and her test password. On phone B use the same server and Bob's credentials. A phone's `localhost` means that phone, not the computer. The standard emulator may use the computer's private IP too; `10.0.2.2` works only when the host listener is bound to a reachable host-gateway interface.

## 6. Exercise the encrypted flow

1. Alice enters Bob's full ID and starts an encrypted conversation. Bob reviews and accepts the invitation.
2. Open Device verification on both phones. Request and accept verification, compare all SAS values through a trusted channel, then approve only if they match. Test cancellation/mismatch separately.
3. Send text in both directions. Share a small harmless file, open it, and compare its contents. An external viewer may retain a plaintext copy.
4. Turn off Alice's Wi-Fi/data. Send a message: it should be queued. Close/reopen the client, reconnect, and check Bob receives one copy. If a phone cannot reach the server, internet connectivity alone cannot fix it.
5. Disconnect Bob, send from Alice, then reconnect/open Bob's Matrix screen. Check missed history arrives. Sent means accepted by the server, not delivered/read. Read receipts and typing sharing are optional.
6. Set up encrypted recovery and privately save the recovery secret. Sign in on a fresh local app/device, recover keys, open the room and tap Load earlier messages if needed. An account password alone does not restore old encryption keys.
7. Restart the server with the same config and volumes; ensure users/history survive. Never delete the volume to fix an ordinary connection error.

The APK's local privacy-test notification works, but **closed-app Matrix push is not implemented just by starting this server**. A compatible UnifiedPush gateway/distributor/receiver remains a separate task. Calls and real background ringing also remain separate. A local server does not turn internet calls into offline radio calls.

## 7. Stop, restart, or change IP

Run the same Compose command ending in `stop` to pause, or `up -d` to resume. `down` removes containers/networks but normally preserves the named database volume. Do not use `down -v` unless deliberately discarding the entire disposable database. The preparation script refuses to regenerate existing config or encryption/signing secrets.

If DHCP changes the computer IP, stop the local stack. Change `MATRIX_LOCAL_IP` in `.env.local` and only `public_baseurl` in `data-local/homeserver.yaml` to the new private origin. Keep `server_name`, all secrets and database credentials unchanged. Restart with `up -d`; it recreates the port binding. Existing app sessions may need a deliberate new disposable vault/account setup for a different origin; never replace a valuable saved session silently. Reserving the computer's DHCP address avoids this during development.

## Later production deployment

Use the base `compose.yaml` without `compose.local.yaml`, a separate project/data directory and a real domain with HTTPS; see [MATRIX_SETUP.md](MATRIX_SETUP.md). Keep public signup/admin endpoints restricted, back up PostgreSQL and signing keys, and provide user encryption recovery separately. The local HTTP APK must not be distributed as a production messenger. No hosting purchase is required for the local steps above.
